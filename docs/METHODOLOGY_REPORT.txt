1. DATASETS USED

1.1 Primary Hyperspectral Data
-------------------------------
- Dataset: NYU_TuckMapping_20190511_Mission1_NE-SW_288Bands.pix
- Format: ENVI/ERDAS Imagine (.pix)
- Total Size: 6,419 x 8,001 pixels (full image)
- Bands: 288 hyperspectral bands
- Data Type: uint16 (0-65535)
- Coordinate System: EPSG:3178 (Albers Equal Area Conic, meters)
- Spatial Resolution: Variable (typically 0.5-1.0 meters per pixel)
- Wavelength Range: Full hyperspectral range (visible to near-infrared)

- Analysis Window: 800 x 800 pixels
- Window Position: (2500, 3000) from top-left corner
- Total Pixels Analyzed: 640,000 pixels

1.2 Ground Truth Data
---------------------
- Dataset: NYC 2017 LiDAR Land Cover Raster
- File: Land Cover Raster Data (2017) – 6in Resolution\Land_Cover\NYC_2017_LiDAR_LandCover.img
- Format: ERDAS Imagine (.img)
- Total Size: 310,844 x 314,414 pixels
- Resolution: 6 inches (0.15 meters)
- Coordinate System: EPSG:2263 (NAD83 / New York Long Island, State Plane, feet)
- Data Type: uint8
- Classes Used:
  * Class 6: Roads
  * Class 7: Other Impervious Surfaces (sidewalks, parking lots, etc.)

- Alignment: Reprojected from EPSG:2263 to EPSG:3178 and resampled to match

- Status: Used when available, pipeline continues gracefully if unavailable

2. METHODOLOGY PIPELINE - STEP BY STEP
================================================================================

2.1 STEP 1: Data Loading and Preprocessing
-------------------------------------------
Method: Load hyperspectral data from .pix file
- Extract 800x800 pixel window from full image
- Load all 288 spectral bands
- Extract geospatial metadata (CRS, transform, bounds)

Why: 
- Full spectral information (288 bands) provides rich material signatures
- Windowed extraction enables memory-efficient processing of large datasets
- Geospatial metadata essential for alignment with ground truth

Output: Hyperspectral data cube (288, 800, 800), profile, transform

2.2 STEP 2: RGB Composite Creation
-----------------------------------
Method: Create false-color RGB composite for visualization
- Band selection: R=70 (NIR), G=50 (Red), B=20 (Green)
- Percentile stretch: 1%-99% for contrast enhancement

Why:
- Visual quality control and result interpretation
- False-color composite highlights vegetation and urban features
- Percentile stretch prevents black/white clipping

Output: RGB composite image (800, 800, 3)

2.3 STEP 3: Data Reshaping for Machine Learning
------------------------------------------------
Method: Reshape 3D hyperspectral cube to 2D feature matrix
- Original: (288, 800, 800) -> Reshaped: (640,000, 288)
- Identify valid pixels (non-zero, non-NaN)

Why:
- Machine learning algorithms require 2D input (samples x features)
- Valid pixel identification removes corrupted or edge pixels

Output: Feature matrix X (640,000 x 288), valid pixel mask

2.4 STEP 3.5: Spectral Masking (Pre-filtering)
-----------------------------------------------
Method: Multi-stage spectral filtering to remove obvious non-pavement
- NDVI filtering: Remove vegetation (NDVI >= 0.3)
- Brightness filtering: Remove shadows/water (low percentile) and bright roofs (high percentile)
- Variance filtering: Remove pixels with high spectral variance (noise/edges)

Parameters:
- NDVI threshold: 0.3
- Brightness percentiles: 5th (low) and 99th (high)
- Variance percentile: 90th

Why:
- Reduces computational load by removing clearly non-pavement pixels
- Focuses analysis on impervious surfaces (roads, sidewalks, rooftops)
- Prevents vegetation from contaminating pavement signatures

Output: Spectral mask (typically 15-20% of pixels retained)

2.5 STEP 4: Advanced Feature Engineering
----------------------------------------
Method: Extract additional features beyond raw spectral bands

Features Added:
a) Spectral Indices (16 features):
   - Vegetation: NDVI, EVI, SAVI
   - Urban: NDBI, UI, IBI
   - Brightness: Brightness, Greenness, Wetness indices
   - Additional: Various ratio and normalized difference indices

b) Sidewalk-Specific Features (8 features):
   - Custom spectral signatures optimized for sidewalk detection
   - Material-specific indices for concrete/asphalt discrimination

c) Statistical Features (8 features):
   - Mean, std, min, max across spectral bands
   - Percentiles and variance measures

d) Spatial Features (20 features):
   - Local mean, std, min, max (3x3 window)
   - Texture measures: entropy, contrast, homogeneity
   - Edge detection features

Total: 288 original bands -> 332 features (+44 features, 1.15x expansion)

Why:
- Spectral indices capture material properties (vegetation, urban, brightness)
- Spatial features capture texture and context (important for distinguishing
  similar materials like roads vs. rooftops)
- Sidewalk-specific features target the primary class of interest
- Statistical features provide robust summaries of spectral variability

Output: Augmented feature matrix (98,919 x 332 features)

2.6 STEP 5: K-Means Clustering
-------------------------------
Method: Unsupervised clustering to identify surface types
- Algorithm: K-Means with k=7 clusters
- Sampling: 50,000 pixels (for computational efficiency)
- Distance metric: Euclidean in feature space

Why:
- Identifies distinct surface types (different pavement materials, rooftops, etc.)
- Provides initial segmentation before supervised classification
- Helps identify pavement clusters based on spectral similarity

Output: Cluster labels (7 clusters), cluster centers, cluster map

2.7 STEP 6: Ground Truth Loading and Alignment
-----------------------------------------------
Method: Load and align LiDAR-derived land cover data
- Reproject from EPSG:2263 to EPSG:3178
- Resample to match hyperspectral resolution (800x800)
- Extract pavement classes (6=Roads, 7=Other Impervious)

Why:
- Provides true ground truth labels (not derived from clustering)
- Enables accurate accuracy assessment
- Eliminates circular dependency (classifier learning from its own predictions)
- LiDAR-derived data is highly accurate for impervious surface classification

Output: Pavement mask (800, 800), land cover classes map

2.8 STEP 7: Dimensionality Reduction (PCA)
------------------------------------------
Method: Principal Component Analysis (PCA)
- Variance threshold: 99.5%
- Components retained: 19 (from 332 features)
- Variance explained: 99.51%

Why:
- Reduces dimensionality while preserving information (99.5% variance)
- Prevents overfitting with high-dimensional feature space
- Speeds up training and prediction
- Removes redundant information (correlated features)

Output: Reduced feature matrix (98,919 x 19), PCA model

2.9 STEP 8: Data Normalization
-------------------------------
Method: Z-score normalization (standardization)
- Formula: (x - mean) / std
- Applied to PCA-reduced features

Why:
- Ensures all features are on same scale
- Prevents features with large values from dominating
- Required for many ML algorithms (including Random Forest, though less critical)

Output: Normalized feature matrix (98,919 x 19)

2.10 STEP 9: Dataset Balancing
-------------------------------
Method: Undersampling majority class
- Original distribution: 62.2% non-pavement, 37.8% pavement
- Balanced to: 50% each class (20,000 samples per class)

Why:
- Prevents classifier bias toward majority class
- Ensures equal learning from both classes
- Improves recall for minority class (pavement)

Output: Balanced dataset (40,000 samples total)

2.11 STEP 10: Train/Test Split
-------------------------------
Method: Stratified random split
- Training: 70% (28,000 samples)
- Test: 30% (12,000 samples)
- Stratification: Maintains class proportions

Why:
- Enables unbiased accuracy assessment
- Prevents data leakage between training and testing
- Standard practice in machine learning

Output: X_train, X_test, y_train, y_test

2.12 STEP 11: Random Forest Training
-------------------------------------
Method: Ensemble of decision trees
- Algorithm: Random Forest Classifier
- Parameters:
  * n_estimators: 300 trees
  * max_depth: 30
  * min_samples_split: 5
  * Random state: 42 (reproducibility)

Why:
- Robust to overfitting (ensemble method)
- Handles non-linear relationships
- Provides feature importance scores
- Fast training and prediction
- Works well with high-dimensional data

Output: Trained classifier, feature importance scores

2.14 STEP 13: Full Image Classification
----------------------------------------
Method: Apply trained classifier to all valid pixels
- Input: Normalized PCA features for all 98,919 valid pixels

Why:
- Creates complete classification map for entire analysis area
- Enables spatial analysis and visualization

Output: Initial classification map (800, 800)

2.15 STEP 14.5: Height-Based Filtering (LiDAR)
-----------------------------------------------
Method: Filter using LiDAR elevation data
- Create DEM from LiDAR point cloud
- Calculate height above ground level (DTM)
- Remove pixels elevated >50cm above ground (rooftops)

Parameters:
- Height threshold: 50 cm
- Method: Ground level (DTM) comparison
- Rooftop exclusion threshold: 5.0 m above ground

Why:
- Distinguishes rooftops (elevated) from sidewalks/roads (ground level)
- Removes false positives from elevated structures
- Preserves ground-level pavement (sidewalks, roads)

Output: Height-filtered classification map

2.16 STEP 15: Multi-Stage Spatial Filtering
--------------------------------------------
Method: Geometric filtering to remove rooftops
- Connected component analysis
- Remove regions that are:
  * Square/compact (aspect ratio <= 1.4)
  * Medium size (300-2500 pixels)
  * Very compact (compactness > 0.85)

Why:
- Rooftops are typically square and compact
- Sidewalks/roads are elongated and less compact
- Geometric properties help distinguish similar materials

Output: Rooftop-filtered classification map

2.17 STEP 15.7: Sidewalk Signature Matching
-------------------------------------------
Method: Expand detection using ground truth signatures
- Extract mean hyperspectral signature from ground truth sidewalk pixels
- Find pixels with similar signatures (cosine similarity >= 0.80)
- Apply spatial constraints (prefer rectangular/linear patterns)
- Expand within 100 pixels of existing detections

Parameters:
- Similarity threshold: 0.80 (cosine similarity)
- Max distance: 100 pixels
- Prefer rectangular: Yes (aspect ratio >= 1.5 or compactness >= 0.5)

Why:
- Ground truth provides accurate sidewalk signatures
- Signature matching finds similar materials missed by classifier
- Spatial constraints ensure realistic sidewalk shapes
- Expands detection to complete sidewalk networks

Output: Expanded classification map (75.7% expansion in test case)

2.18 STEP 16: Morphological Filtering

Method: Light morphological operations
- Kernel size: 1 (very light)
- Purpose: Smooth edges, remove small noise

Why:
- Removes isolated pixels and small artifacts
- Smooths classification boundaries
- Minimal impact on overall results

Output: Final classification map

3. RATIONALE FOR METHODOLOGY CHOICES
================================================================================

3.1 Why Use All 288 Bands?
--------------------------
- Full spectral information captures material properties across entire spectrum
- More information = better discrimination between similar materials
- Modern computational resources enable processing of full spectral data
- PCA reduces dimensionality while preserving information

3.2 Why Ground Truth Instead of Clustering Labels?
--------------------------------------------------
- Clustering labels are derived from data itself (circular dependency)
- Ground truth provides independent validation
- Enables true accuracy assessment (not inflated by label agreement)
- Research validity: publishable results require independent ground truth

3.3 Why Multi-Stage Filtering?
------------------------------
- Single-stage classification insufficient for complex urban scenes
- Different filters target different false positives:
  * Spectral masking: vegetation, water
  * Height filtering: rooftops (elevated structures)
  * Geometric filtering: square rooftops
  * Signature matching: complete sidewalk networks
- Sequential filtering refines results progressively

3.4 Why Feature Engineering?
----------------------------
- Raw spectral bands may not capture optimal material properties
- Spectral indices designed for specific materials (vegetation, urban)
- Spatial features capture texture and context
- Statistical features provide robust summaries
- Sidewalk-specific features target primary class of interest

3.5 Why Random Forest?
----------------------
- Robust to overfitting (ensemble method)
- Handles high-dimensional data well
- Provides feature importance (interpretability)
- Fast training and prediction
- Works well with mixed feature types (spectral + spatial)

3.6 Why PCA Dimensionality Reduction?
--------------------------------------
- 332 features is high-dimensional (curse of dimensionality)
- PCA preserves 99.5% variance with only 19 components
- Reduces computational cost
- Prevents overfitting
- Removes redundant information
